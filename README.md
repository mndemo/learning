What “auto-embedded, no env var” means in practice
You have two sources of truth Spring Boot can read automatically at build time — no flags, no env vars, no CI changes needed:
BuildProperties (generated by Spring Boot’s buildInfo Gradle task).
Auto-populated fields include:
build.time → the moment Gradle built the JAR (ISO timestamp, baked into META-INF/build-info.properties).
build.version → Gradle project.version (0.0.1-SNAPSHOT today).
GitProperties (generated by the com.gorylenko.gradle-git-properties plugin you already have on line 6 of build.gradle).
Auto-populated fields include:
git.commit.id.abbrev → short SHA of the commit being built (e.g. a1b2c3d).
git.commit.time → commit timestamp.
Both are dumped into the JAR at assemble time and are identical no matter which environment runs the image. No one sets anything.
A clean human-readable label combining both, like:
> Build 2026-04-20 · a1b2c3d
…is unique per build, self-describing, and never needs human input.

How it auto-populates (no human input anywhere)
Build time — Spring Boot’s buildInfo Gradle task writes a timestamp into build/resources/main/META-INF/build-info.properties every time ./gradlew assemble runs. Gets sealed into the JAR.
Git short SHA — the com.gorylenko.gradle-git-properties plugin (already on line 6 of build.gradle) writes git.properties with git.commit.id.abbrev during the same build step. Also sealed into the JAR.
At runtime, Spring Boot auto-creates BuildProperties and GitProperties beans from those files.
ShibaGlobalModelAttributes reads both, formats yyyy-MM-dd · <shortSha>, and exposes it as the shibaBuildVersion model attribute — which your existing footer templates already render.
So a deployed image ends up showing something like:
> Version: Build 2026-04-20 · a1b2c3d
…and it shows the same value in dev, ATST, and prod because it’s embedded in the jar, not read from the environment.
A couple of behaviors worth knowing
OpenShift BuildConfig (ATST): the build pod clones the repo via source.git, so .git exists in the build context → git SHA is captured correctly. No extra config needed.
Local bootRun without a build: if you run straight from the IDE without invoking buildInfo, BuildProperties may not exist — the footer will show just the SHA, or an empty string if neither file is present. That’s the graceful fallback in the new class.
0.0.1-SNAPSHOT in build.gradle: still sets project.version. It’s used for the JAR filename and build.version attribute, but the footer no longer displays it. Leave it or bump it at your leisure.
How to verify locally
./gradlew clean assemble
ls build/resources/main/META-INF/
# should contain build-info.properties and git.properties
unzip -p build/libs/*.jar BOOT-INF/classes/META-INF/build-info.properties
unzip -p build/libs/*.jar BOOT-INF/classes/META-INF/git.properties
Run the jar (java -jar build/libs/*.jar) and view any page with the footer — you should see Build <today’s date> · <short SHA>.
If it ever goes live and shows only a date (no SHA) or only a SHA (no date), that tells you exactly which metadata file didn’t make it into the JAR.

package org.codeforamerica.shiba.config;

import java.time.ZoneOffset;
import java.time.format.DateTimeFormatter;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.info.BuildProperties;
import org.springframework.boot.info.GitProperties;
import org.springframework.util.StringUtils;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ModelAttribute;

/**
 * Footer build label. Auto-derived at build time from JAR metadata, so the same image always shows
 * the same value regardless of the runtime environment — no env vars, no CI flags needed.
 *
 * <ul>
 *   <li>{@code build.time}: baked into {@code META-INF/build-info.properties} by Spring Boot's
 *       {@code buildInfo} Gradle task.</li>
 *   <li>{@code git.commit.id.abbrev}: baked into {@code META-INF/git.properties} by the
 *       {@code com.gorylenko.gradle-git-properties} plugin.</li>
 * </ul>
 *
 * Renders as e.g. {@code "Build 2026-04-20 · a1b2c3d"}. Falls back gracefully if either metadata
 * file is missing (e.g. local {@code bootRun} without a build, or checkout without {@code .git}).
 */
@ControllerAdvice
public class ShibaGlobalModelAttributes {

  private static final DateTimeFormatter DATE_FORMAT =
      DateTimeFormatter.ofPattern("yyyy-MM-dd").withZone(ZoneOffset.UTC);

  private final BuildProperties buildProperties;
  private final GitProperties gitProperties;

  public ShibaGlobalModelAttributes(
      @Autowired(required = false) BuildProperties buildProperties,
      @Autowired(required = false) GitProperties gitProperties) {
    this.buildProperties = buildProperties;
    this.gitProperties = gitProperties;
  }

  @ModelAttribute("shibaBuildVersion")
  public String shibaBuildVersion() {
    String date = buildDate();
    String sha = shortSha();
    if (StringUtils.hasText(date) && StringUtils.hasText(sha)) {
      return date + " · " + sha;
    }
    if (StringUtils.hasText(date)) {
      return date;
    }
    if (StringUtils.hasText(sha)) {
      return sha;
    }
    return "";
  }

  private String buildDate() {
    if (buildProperties == null || buildProperties.getTime() == null) {
      return "";
    }
    return DATE_FORMAT.format(buildProperties.getTime());
  }

  private String shortSha() {
    if (gitProperties == null) {
      return "";
    }
    String sha = gitProperties.getShortCommitId();
    return sha != null ? sha.trim() : "";
  }
}
