What “auto-embedded, no env var” means in practice
You have two sources of truth Spring Boot can read automatically at build time — no flags, no env vars, no CI changes needed:
BuildProperties (generated by Spring Boot’s buildInfo Gradle task).
Auto-populated fields include:
build.time → the moment Gradle built the JAR (ISO timestamp, baked into META-INF/build-info.properties).
build.version → Gradle project.version (0.0.1-SNAPSHOT today).
GitProperties (generated by the com.gorylenko.gradle-git-properties plugin you already have on line 6 of build.gradle).
Auto-populated fields include:
git.commit.id.abbrev → short SHA of the commit being built (e.g. a1b2c3d).
git.commit.time → commit timestamp.
Both are dumped into the JAR at assemble time and are identical no matter which environment runs the image. No one sets anything.
A clean human-readable label combining both, like:
> Build 2026-04-20 · a1b2c3d
…is unique per build, self-describing, and never needs human input.
